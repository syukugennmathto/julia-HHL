# 論文の骨組み ― 主張を 1 本に絞る

現状、リポジトリには**主張が 4 本**混ざっている:
再現性・性能・定数時間・仕様書の穴。
1 本の論文にできるのは 1 本だけである。

---

## 選ぶ主張

> **仕様書だけを読んで書いた独立実装は、参照実装の署名をビット単位で
> 再現できるか。できないとすれば、仕様書が固定していないのはどこか。**

理由:

1. **答えが出ている。** 再現できた（#050）。中途半端な主張ではない。
2. **否定側も測ってある。** 「浮動小数点が原因」という広く信じられた説明を、
   修正を戻す A/B で反証した（480 署名・245760 係数で差 0）。
3. **時期が合っている。** FIPS 206 は演算順序を規定し FMA を禁じ、
   署名が KAT に bit 一致することを要求する方向である（`docs/refs.md`）。
   本稿が挙げる箇所は、**規範として書かれる必要がある候補**である。
4. **他の 3 本を従属させられる。** 性能と定数時間は
   「同じ実装・同じ道具立てで測ったもう一つの結果」として節・付録に落ちる。

**捨てる主張**（本稿では主結果にしない）:

- 性能。C と同着〜2 倍遅いという結果は、それ自体では論文にならない。
  §「実装」で範囲比較として述べ、`docs/why_julia.md` の内容を短く引く。
- 定数時間。攻撃を示していないので主結果にできない。付録に落とす。
- Julia であること。手段であって主張ではない。§1 で動機として述べるだけ。

## 構成案

### 1. Introduction

- FALCON / FN-DSA は署名が**浮動小数点の関数**である唯一の NIST 標準候補。
- FIPS 206 は KAT との bit 一致を要求する方向。
  **ならば「仕様書だけで参照実装と同じ署名が作れるか」は規範上の問いである。**
- 本稿の動機（正直に）: 我々は速度を期待して Julia を選んだ。
  期待は部分的にしか当たらなかったが、**別言語で書いたことが
  仕様書と参照実装の差を可視化した**。
- 貢献:
  1. 独立実装による**ビット単位の署名再現**と、その必要条件の測定
  2. 仕様書と参照実装が代数的に同値で丸めが異なる**3 箇所**の特定
  3. 仕様書が値しか与えていない定数の**導出の復元**と、
     参照実装の定数表が仕様書の値と 1〜2 ulp 食い違うことの指摘
  4. 上記が署名に**伝播しない**ことの定量（0/480 署名）

### 2. Background

- FALCON の署名生成、ffLDL 木、ffSampling、SamplerZ
- なぜ浮動小数点が本質か（FPEMU の存在理由）
- **関連研究**（未着手 ― §「やること」参照）

### 3. Methodology

ここは**弱点ではなく強み**として書く。本リポジトリの記録は
計測器の失敗を 6 回含んでおり、そのすべてが対照によって検出された。

- 比較は**生の 64 bit パターン**で行う。「1e-12 で一致」は
  `samplerz` が中心を丸める以上、何も言っていない。
- 変更の効果は**変更を戻して**測る（#043、#044、#050）。
- 計測器には**陽性・陰性の対照**を常設し、雑音床を実測する（#051）。
- C は**ビルドの集合**として測る（#052）。
- Julia は**run 間の幅**を出す。

### 4. Bit-exact reproduction

- 実験装置: 参照実装を共有ライブラリにし、`prng` の 56 バイト状態を
  直接与える shim（`scripts/cref_shim.c`）。
  **これが本当の障害だった** ― 参照実装の公開 API は
  サンプラの ChaCha20 を内部で SHAKE から導出するので、
  乱数を固定する手段がなかった。
- 段階的な突き合わせ（`scripts/cmp_cref_fp.jl`）:
  - 無改修で bit 一致: `fft` `ifft` `split_fft` `merge_fft`
    `add` `sub` `mul` `adj` `mul*adj` `mul*selfadj`、`B0` 行列
  - 書き方を合わせて一致: 複素除算、`LDL*` の `D11`、
    `ffSampling` の最下 2 段
  - 規約が違う: 木の葉（互いの逆数）、`fpr_inv_sigma`
- 結果: 展開秘密鍵 5120/5120、`s2` 25/25、圧縮バイト 25/25
- **反証**: 3 箇所を戻しても再現する。480 署名・245760 係数で差 0。
  → **「浮動小数点の書き方の差」は署名に伝播しない。**
  伝播しないのは `berexp` の判定余裕が 1 ulp より桁違いに大きいためで、
  1 draw あたりの反転確率は 2^-52 程度、1 署名で 2^-43 程度。

### 5. What the specification does not pin down

- **(a) `σ` と `σ_min` は別の ε から出ている。**
  σ は (2.13) を `ε ≤ 1/√(Q_s·λ)` で評価した値（相対誤差 2e-16 で再現）、
  σ_min は `1/√(2^64·n³)` での平滑化パラメータ（3e-13 で再現）。
  仕様書は後者の ε を印字していない。取り違えると 10% ずれる。
- **(b) `fpr_inv_sigma` は Table 3.3 の σ の正しい逆数ではない**
  （logn=9 で 1 ulp、logn=10 で 2 ulp）。
  参照実装はこの表を掛けるので、逆数を計算しても再現しない。
- **(c) SamplerZ のテストベクタ（Table 3.2）の replay 規約**が
  本文に書かれていない（9 バイトを 72 bit 語に組む順序）。
- **(d) 三つの「書き方」**（§4）。同値なので仕様書は区別していないが、
  bit 一致を要求するなら区別が要る。

→ **FIPS 206 への含意**: (a)(b) は値の出所を、(d) は演算順序を、
   本文で固定する必要がある。

### 6. Implementation notes（従属）

- 鍵生成 9610 → 11 ms。効いたのは全部**確保の除去**であって
  高水準の配列演算ではない。Karatsuba が schoolbook に n=2〜2048 で全敗。
- 性能は範囲比較で: `verify` 同着、`sign` は FPEMU 帯より速く native 帯に 7 倍負け、
  `keygen` は FPEMU 帯。

### 7. Timing leakage（付録）

- 脅威モデル（受理署名は公開／棄却候補は非公開）
- dudect + 対照 + 実測雑音床
- 見つけた最大の漏洩は**自分の実装の欠陥**であり参照実装には無い。
  一般化できる教訓は「漏れるのはデータ依存分岐があることではなく、
  分岐結果が一方のクラスで学習可能で他方で不能であること」。
- Julia では処理系と FPU 由来の変時間性を閉じられない、と明示。

### 8. Conclusion / Limitations

- 単一マシン。マイクロアーキテクチャ 1 種。
- 攻撃は示していない。
- FIPS 206 未発行なので、指摘は round-3 仕様書に対するもの。
