# 同じアルゴリズムを、同じデータ配置で、Julia と C に書いて比べる

`docs/benchmarks.md` の表では、この実装は C 参照実装より
鍵生成で 16〜35 倍、検証で 6.5 倍遅い。
そこで当然の疑問が出る ― **「本来なら Julia は C と同じ速度が出るはずでは？」**

この疑問には、あの表では答えられない。あの表には**三つの別の差**が
混ざっているからである:

1. **言語の差** ― 同じアルゴリズムを同じ書き方で書いたときの差
2. **アルゴリズムの差** ― 我々は `BigInt` の降下と O(n²) の畳み込み、
   C は RNS と in-place NTT
3. **メモリ規律の差** ― C は呼び出し側が渡した 1 個のスクラッチに書き込み、
   我々は関数ごとに新しい配列を返す

2 と 3 は「仕様どおりに読めるコードを書く」ことを優先して**意図的に**
選んだものであって、言語とは関係がない。
1 だけを取り出すには、**同じアルゴリズムを両言語で書いて比べる**しかない。

## 何を比べているか

`Falcon.polymulq` ― `Z_q[x]/(x^n+1)` の学校算法による積。
`same.c` はその逐語訳で、意図的に**最適化していない**:
同じループ順、同じ `int64` アキュムレータ、同じ負巡回の符号、
同じ最終剰余（Julia の `mod` は非負を返すので C 側で合わせてある）。
`restrict` も intrinsics も手展開も無い。

両側は**同じ LCG で入力を作る**ので、同じ多項式を掛けている。
出力の checksum を両方が印字するので、
**一致しなければ比較そのものが無効**だと分かる。

## 走らせ方

```sh
cc -O2 -o same same.c && ./same 512 300
julia --project=falcon falcon/scripts/langcmp/same.jl
```

C 側には最善を尽くさせること。`-O2` だけで比べて
「Julia が勝った」と言うのは不誠実である。実測では
`gcc -O3` は `-O2` より**遅く**（0.397 対 0.281 ms）、
最も速かったのは `clang -O3 -march=native`。

## 結果（x86-64、gcc 13.3 / clang、Julia 1.12.7）

| n | Julia | C (clang -O3 -march=native) | 比 |
|---:|---:|---:|---:|
| 128 | 0.0100 ms | 0.0152 ms | Julia 1.52x 速い |
| 256 | 0.0363 | 0.0555 | 1.53x |
| 512 | 0.1563 | 0.2177 | 1.39x |
| 1024 | 0.6218 | 0.8690 | 1.40x |

gcc での内訳（n=512）:

| flags | median ms |
|:---|---:|
| `-O2` | 0.281 |
| `-O3` | 0.397 |
| `-O3 -march=native` | 0.276 |
| `-Ofast -march=native` | 0.281 |
| `-O3 -march=native -funroll-loops` | 0.262 |
| `clang -O3 -march=native` | **0.228** |
| **Julia** | **0.156** |

## 読み取り

**同じアルゴリズムを同じ書き方で書けば、Julia は C と同等かそれ以上である。**
4 つの次数すべてで再現し、checksum も一致する。
Julia も C（clang）も LLVM に降りるので、これは驚くことではない ―
驚くとすれば「Julia だから遅い」という前提のほうである。

したがって `docs/benchmarks.md` の 16〜35 倍は**言語の差ではない**。
残る 2 つ、**アルゴリズムの差とメモリ規律の差**である。
そしてその 2 つは我々が選んだものなので、**変えられる**
（実際 #034 と #036 で、値を 1 bit も変えずに鍵生成が 42 倍速くなった）。

一つ注意。この結果を「Julia は C より速い」と一般化してはいけない。
測ったのは**1 つのカーネル**であり、しかもコンパイラは
このループを自動ベクトル化しやすい形をしている。
言えるのは「**この形のコードで、Julia が言語として不利ということはない**」
までである。
