# 定数時間性 ― 脅威モデル・棚卸し・実測

このプロジェクトは当初から「定数時間性はスコープ外」と宣言してきた。
その宣言は**撤回しない**。撤回できるだけの実装ではないからである。
しかし「スコープ外」は「調べていない」の同義語であってはならない。
本文書は、

1. **何を守ろうとしているのか**（脅威モデル）、
2. **どこが変時間なのか**（棚卸し）、
3. **実際に何が漏れているのか**（実測）、
4. **何を直したか、何が直せないか**、

を分けて述べる。3 の手続きと生データは `scripts/dudect.jl`。

---

## 1. 脅威モデル

### 1.1 何が秘密か

FALCON の署名者が持つ秘密は**短基底 `(f, g, F, G)`** と、そこから導かれる
FFT 基底・ffLDL 木である。攻撃者の目的は署名の観測（および署名時刻の観測）
から基底を復元することで、それができれば任意のメッセージに署名できる。

**重要な区別**: 署名 `(salt, s2)` は**公開される**。
`s1 = c − s2·h mod q` も公開鍵とメッセージから誰でも計算できる。
したがって

> **受理された署名の値についてタイミングが漏らす情報は、
> 攻撃者が署名そのものから得る情報を超えない。**

これは本文書の解釈の要である。同じ「変時間」でも、
`sample_preimage` の内部（秘密基底の座標）と
`compress_sig` の入力（公開される `s2`）では意味が違う。

### 1.2 何が秘密で「ない」ように見えて秘密か

三つある。

- **棄却された候補**。`falcon_sign` は `‖(s1,s2)‖² ≤ ⌊β²⌋` を満たすまで
  再標本する。棄却された候補は公開されない。
  その値についての漏洩は、公開情報で説明できない。
- **棄却の回数**。鍵とメッセージに依存する。
- **`ffSampling` の中間値**。木の葉の `σ` は基底の Gram-Schmidt ノルムであり、
  これは Fouque–Kirchner–Tibouchi–Wallet–Yu（eprint 2019/1180）の
  「Gram-Schmidt ノルムの漏洩からの鍵復元」がまさに標的にした量である。

### 1.3 攻撃者モデル

**同一ホスト・高分解能タイマ**を仮定する。すなわち攻撃者は署名 1 回ごとの
実行時間を ns 分解能で観測でき、同じ鍵で何度でも署名させられる。
これは（リモートよりはるかに強いが）共有クラウド上の実装にとって
現実的な仮定であり、`dudect` が想定するモデルでもある。

**仮定しない**もの: 電力・電磁波・キャッシュのプローブ（Flush+Reload 等）。
本実装のメモリアクセスパターンは明らかにデータ依存であり、
そこは測っていない。

## 2. 棚卸し ― どこが変時間か

`src/` の `CONSTANT TIME:` 注記が網羅的な一覧である（23 箇所）。
分類すると:

| 分類 | 箇所 | 秘密に触るか |
|:---|:---|:---|
| **A. 構造的に定数時間** | `shake.jl`（Keccak, ChaCha20）、`ntt.jl` の変換本体、`fft.jl` の変換本体 | ― |
| **B. 秘密に触るが公開値のみ** | `encoding.jl` の圧縮・展開、`falcon.jl` の検証 | 受理署名のみ |
| **C. 秘密に触り、棄却候補にも触る** | `falcon.jl` の再標本ループ、`poly.jl` の `sqnorm` | **はい** |
| **D. 秘密基底そのものに触る** | `ffsampling.jl` 全体、`samplerz.jl` 全体 | **はい** |
| **E. 鍵生成** | `ntrugen.jl` | 鍵生成は 1 回きり。仕様も定数時間を要求していない |

D が本丸である。参照実装が浮動小数点を**整数で эмуレート**（FPEMU）している
のは、まさに D を定数時間にするためであって、速度のためではない。

## 3. 実測 ― `scripts/dudect.jl`

### 3.1 手続き

Reparaz–Balasch–Verbauwhede（DATE 2017）の "dude, is my code constant time?"
に従う。2 クラス（固定入力／乱択入力）で実行時間を測り、
Welch の t 検定で分布が区別できるかを見る。
機械のモデルを要らないのが利点で、**「漏れているか」には答えるが
「どれだけ漏れているか」には答えない**のが限界である。

この実装で加えた手当ては 5 つあり、どれも**入れなかったときに嘘の数字が
出た**ので入っている:

1. **陽性・陰性の対照を毎回走らせる。**
   「漏れなし」は、その計測器が漏れを検出できると示されて初めて意味を持つ。
   陽性対照 2 本（合成 1 本＋`falcon_verify` の有効／改竄 1 本）、
   陰性対照 2 本（固定仕事量、`basesampler`）。
2. **クラスを交互ではなくコイン投げで選ぶ。**
   周波数ドリフトや GC がクラス標識に相乗りしないように。
3. **両クラスの入力を、ループの前に全部作る。**
   最初の版は `prepare_random()` をループ内で呼んでいて、
   陰性対照が t = −5.46 を出した。乱択側だけが `rand` と確保をしてから
   計測区間に入るので、キャッシュと分岐予測器の状態が系統的に違っていた。
   **測定の外にあり、実験の中にある非対称。**
4. **両クラスとも「別オブジェクト」を同数巡回させる。**
   固定クラスが同一配列を読み続けると、それだけでキャッシュが効く。
   これを直す前は `sqnorm` が t = −16.3 を出していた ―
   `sqnorm` の性質ではなく、こちらの実験設計の性質である。
5. **雑音床を毎回実測し、それに対して判定する。**
   dudect の |t| > 4.5 は測定間独立を仮定した閾値である。
   この環境ではその仮定が n とともに壊れ、
   **入力を持たない `basesampler` が n = 100000 で t = 11.61** を出した。
   そこで陰性対照の max|t| を雑音床とし、
   **4.5 を超え、かつ雑音床の 3 倍を超えたときだけ**漏洩と判定する。

### 3.2 `t` は漏れの大きさではない

これは実際に踏んだ罠なので明記する。
`compress_sig` を速く・低分散にしたら、**同じ絶対差に対して `t` が上がった**
（323 → 913）。t は「区別できるか」の統計量で、分散が小さくなれば上がる。
そこで効果量は**中央値の差**を併記する。
しかも中央値差は**打ち切り前の標本**から取る ―
`|t|` を最大化する打ち切りで取ると、`compress_sig` で −6465 ns、
つまりその関数の全実行時間（中央値 5.2 µs）より大きい値が出た。
打ち切りは**検定を鋭くする道具**であって、**大きさを述べる道具ではない**。

### 3.3 結果

n = 100000（署名は 10000）、Xeon 2.10GHz、Julia 1.11.9。
`x floor` は雑音床の倍数。

## 4. 直したもの

### 4.1 `compress_sig` ― 分岐予測が犯人だった

一見の容疑者は **unary 列**である。
係数 `a` に対して `a >> 7` 個のゼロを書くループがあり、
仕事量が係数の大きさに比例する。

**これは犯人ではなかった。**
出力領域はゼロ初期化されているので、ゼロを書く必要がそもそも無い ―
位置を進めるだけでよい。そう直したら **`t` は 323 から 913 に上がった**。

真犯人は**条件付きビット書き込み**だった。
符号 1 bit ＋ 下位 7 bit を `cond && setbit!(pos)` で書いていて、
1 係数あたり 8 本、1 署名あたり 4096 本の**データ依存分岐**になる。
同じ署名を繰り返し圧縮すると分岐予測器が 4096 本すべてを学習し、
**違う署名を混ぜると外す**。

    同一署名を繰り返し圧縮        中央値 5591 ns
    異なる署名を混ぜて圧縮        中央値 15327 ns   ← 2.7 倍

修正は `putbit!(i, b)` を分岐なしにするだけである:

    out[(i >> 3) + 1] |= UInt8((b & 1) << (7 - (i & 7)))

符号も `c < 0` ではなく `(c >>> 63) & 1` で値として取る。結果:

    同一署名                      中央値 4741 ns
    異なる署名                    中央値 4741 ns   ← 差 0 ns

**しかも速い方の 5591 ns より速くなった。**
定数時間化と高速化が同じ方向を向いた稀な例である。

### 4.2 `sqnorm` ― 署名用の経路を分けた

`sqnorm` は係数を走査して `Int128` と `BigInt` を切り替える。
`ntrugen.jl` の降下では本当に数千 bit になるので汎用版には必要だが、
**署名の受理判定では不要**である。候補の係数は丸めで作られ、
型と長さ（公開情報）だけから `Int128` が安全だと言える。

`sqnorm_machine(v1, v2)` を分けた ― 分岐なし・確保なし・`@simd`。
`falcon_sign` はこちらを使う。この入力には**棄却される候補**が含まれるので、
公開値ではない（§1.2）。

    sqnorm（汎用）        t = +19.3   12.6x floor
    sqnorm_machine        t = −2.0     1.3x floor

## 5. 直せていないもの

### 5.1 残っている通路（この実装）

- **`compress_sig` の書き込み先アドレス**が `pos` に依存する。
  `pos` は `a >> 7` で進むのでデータ依存であり、
  可変長符号である限りどう書き直しても消えない。
  キャッシュラインを観測できる攻撃者には見える。
- **`compress_sig` の早期 return**（入りきらない候補）。
  これが起きると署名は再標本する。その候補は公開されない。
- **再標本の回数**（`falcon_sign`）。鍵とメッセージに依存する。
  実測で `falcon_sign` 全体が雑音床の 4.7 倍・Δ中央値 5.2 µs
  （署名 1 回 ≈ 1 ms の 0.5%）を示しており、**ここが残差である**。
- **`samplerz` の試行回数**。仕様の `SamplerZ` は
  Howe–Prest–Ricosset–Rossi の isochronous 設計に基づくが、
  本実装は `ccs` の作り方を仕様どおりにしているだけで、
  isochronous 性を自分で検証してはいない。
  実測では雑音床の 1.0〜4.6 倍で、Δ中央値は数 ns。

### 5.2 Julia では閉じられないもの

ここが正直に書くべき部分である。**この言語では定数時間を保証できない。**

1. **`ifelse` が分岐にならない保証がない。**
   Julia は `ifelse` を「分岐なし」と規定していない。
   LLVM が `select` に落とすことが多いが、それは最適化の結果であって
   言語の約束ではない。バージョンが変われば変わりうる。
2. **GC が走る。**
   確保のある経路は、確保量に応じて回収を誘発する。
   本実装は `BigInt` と一時配列を多用しており、
   #044 では降下時間の 55% が確保だった。
   回収の発生時刻は入力に依存しうる。
3. **JIT の特殊化。**
   同じ関数が引数の型・値の履歴によって別のコードにコンパイルされうる。
4. **浮動小数点そのもの。**
   これが本丸である。`ffSampling` は秘密基底の座標に対して
   除算・平方根を含む倍精度演算を行う。
   x86-64 の `divsd` / `sqrtsd` はオペランド依存の遅延を持ちうるし、
   非正規数はさらに遅い。
   **参照実装が FPEMU（整数による浮動小数点の完全模倣）を用意しているのは、
   この一点のためである。**
   Julia で同じことをするなら `fpr.c` を丸ごと移植することになり、
   それは「Julia で書く」という本プロジェクトの前提と衝突する ―
   移植した瞬間、C の整数演算を Julia で書き直しただけになる。

したがって本実装の正直な立場は:

> **アルゴリズム由来の変時間性は減らせるし、実際に減らした。
> 言語処理系と浮動小数点ユニット由来の変時間性は、
> Julia で書く限り閉じられない。**

FIPS 206 が浮動小数点の演算順序を規定し FMA を禁じ、
署名が KAT に bit 一致することを要求する方向であること（`docs/refs.md`）は、
この問題を規範の側から締める動きである。
そこで要求されるのは**値の再現性**であって定数時間性ではないが、
両者は同じ根（浮動小数点の実装自由度）から出ている。

## 6. 再現手順

```sh
julia --project=falcon falcon/scripts/dudect.jl 100000
```

対照が落ちたら（`HARNESS BROKEN` / `FALSE POSITIVE`）、
その run の数字は証拠にならない。スクリプトは終了コード 1 を返す。

雑音床は run ごと・機械ごとに違う。**他所の機械の数字と直接比べないこと。**
比べるなら、同じ run の中の雑音床比で比べる。
