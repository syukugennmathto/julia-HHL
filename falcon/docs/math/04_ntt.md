# モジュール 4: NTT ― 「多点評価」だと思えば全部わかる

## 4.1 この章で答える問い

Dilithium を移植したときの NTT は、こういう形をしていた。

```c
for (len = 128; len > 0; len >>= 1)
    for (start = 0; start < 256; start = j + len)
        zeta = zetas[++k];
        for (j = start; j < start + len; ++j) { ... }
```

反復ループ、ビット反転順の出力、Montgomery 形式の twiddle。速い。
ところが FALCON の参照実装（Python 版）の NTT は**再帰**で書かれていて、
しかも `split` / `merge` という、FFT と同じ名前の関数を使っている。

なぜ FALCON は遅い書き方をするのか。答えは
**FALCON には変換が 2 つある**からである。

## 4.2 NTT とは多点評価である

余計な装飾を全部剥がすと、NTT はこれだけの主張だ。

`Z_q` 上で `x^n + 1` が相異なる 1 次式に分解するなら、CRT より

```
Z_q[x]/(x^n+1)  ≅  Z_q × Z_q × ... × Z_q      (n 個)
      f         ↦   (f(w_1), ..., f(w_n))
```

**この写像が NTT である。** 環同型なので、積は成分ごとの積になる。
バタフライも twiddle もビット反転も、
「n 点での評価を O(n²) でなく O(n log n) でやる」ための帳簿にすぎない。

本実装のテストはこの主張を直接検査している:

```julia
@test ntt(f)[j] == f(ntt_roots(n)[j]) mod q      # Horner で評価
```

これが通れば、バタフライがどう並んでいようと変換は正しい。
逆に言えば、**往復（intt∘ntt = id）だけを見ても意味がない**。
評価点が全部間違っていても往復は通るからだ。

## 4.3 なぜ 2n 乗根が要るのか ― 符号の 2 回目

poly.jl の `x^n = -1` が、ここで 2 度目の姿を見せる。

巡回環 `Z_q[x]/(x^n - 1)` なら評価点は n 乗根で、`x^n - 1 = Π(x - w^j)`。
しかし我々の環は

```
x^n + 1 = Π_{j=0}^{n-1} (x - ζ^{2j+1}),   ζ は原始 2n 乗根
```

**根は 2n 乗根のうち奇数乗**であって、n 乗根ではない。
`(ζ^{2j+1})^n = ζ^{n(2j+1)} = (ζ^n)^{2j+1} = (-1)^{2j+1} = -1` だから確かに
`x^n+1` の根になる。

よって条件は `2n | q - 1`。`q - 1 = 12288 = 3·2^12` なので `2n ≤ 4096`、
つまり `n ≤ 2048` まで対応できる。FALCON の `n = 1024` には十分。

## 4.4 根のテーブルは「塔」そのもの

参照実装は `roots_dict_Zq[n]`（n=2..1024、計 2046 個）を sage スクリプトで
生成してハードコードしている。本実装はハードコードせず、**生成する**。
そのほうが「なぜその順序なのか」が見えるからだ。

### 生成則

底: `x^2 + 1` の根は `ζ^{512}` と `ζ^{1536}`（ζ は位数 2048、`ζ^{1024} = -1`）。

1 段上がる: `x^n + 1` の根 `w` に対し、`x^{2n} + 1` の根で `w` の上にあるのは
`±√w` のちょうど 2 つ。指数で書けば

```
e  ↦  { e/2,  e/2 + 1024 }
```

これは代数的には

```
Q(ζ_4) ⊂ Q(ζ_8) ⊂ ... ⊂ Q(ζ_{2n})
```

が 2 次拡大の塔である、という事実を mod q で読んだものにほかならない。
**根のテーブルは塔の各ノードのラベルである。**

### 順序は飾りではない

各ペアの中では、参照実装は**小さい剰余を先**に置く（ペアは必ず `(r, q-r)`）。
これは恣意的な約束に見えるが、この順序でないと `split_ntt` / `merge_ntt` が
`polysplit` / `polymerge` と噛み合わない。

実際、本実装では ζ = 7（12289 を法とする位数 2048 の最小の元）から
この規則で生成したテーブルが、参照実装のハードコード表と
**n = 2 から 1024 まで全て一致する**ことを確認した。
2046 個の数を写経する代わりに、20 行の再帰と 1 個の定数 `ζ = 7` で済む。

## 4.5 バタフライの導出

`f(x) = f0(x²) + x·f1(x²)` に `w` を代入するだけ。

`v = w²` とすると `v` は `x^{n/2}+1` の根で、

```
f( w) = f0(v) + w·f1(v)
f(-w) = f0(v) - w·f1(v)
```

これが `merge_ntt`。`±w` がペアで現れるのが、根のテーブルを
ペアで並べる理由である。逆に解けば

```
f0(v) = (f(w) + f(-w)) / 2
f1(v) = (f(w) - f(-w)) / (2w)
```

これが `split_ntt`。2 の逆元 `i2 = 6145` と根の逆元が要る。

## 4.6 可逆性 ― 「部分的に可逆」は存在しない

`x^n + 1` が相異なる 1 次式に分解するので、`R_q` は体 `Z_q` の n 個の直積。
したがって

> `f` が `R_q` で可逆 ⟺ NTT 係数が 1 つも 0 でない

中間の状態が無い。これが鍵生成で
「`f` の NTT に 0 があったら引き直す」という素朴な判定で済む理由である
（`ntrugen.py:236-238`）。

`h = g/f mod q` が公開鍵なので、**`f` は可逆でなければならない**。

## 4.7 定数時間性 ― ここで 1 つ目の穴が開く

NTT の変換自体は安全である。制御フローは `n` にしか依存せず、`n` は公開。

危ないのは**割り算**のほうだ。

- 参照実装（Python）は `inv_mod_q` という **12289 要素のルックアップ表**を持つ。
  **秘密の値で表を引く**のは教科書的なキャッシュタイミング漏洩。
  本実装は Fermat の小定理（`x^{q-2}`）で計算している。
- `polydivq(g, f)` の除数は**秘密鍵 `f`** である。しかも
  「可逆かどうか」の判定結果自体が秘密に依存する。
  本実装は `Bool` を返して分岐する。C 参照実装は
  `Zf(is_invertible)`（`inner.h:628`）で、bool ではなく**マスク**を返す
  分岐なしの形で書いている。

つまり FALCON では、**NTT は安全だが NTT を使う割り算が危ない**。
これはまだ小さな穴で、本命はモジュール 7・8 で開く。

## 4.8 なぜ再帰で書くのか（Dilithium との対比）

| | Dilithium | FALCON |
|:---|:---|:---|
| 変換 | NTT だけ | **NTT と FFT の 2 つ** |
| 書き方 | 反復 Cooley-Tukey | 再帰 split/merge |
| 出力順 | ビット反転 | 自然順（塔の順） |
| 表現 | Montgomery 形式 | 素直な剰余 |
| 目的 | 速度 | **FFT と構造を揃えること** |

FALCON では、`ffLDL` も `ffSampling` も `NTRU 求解`も、
すべて「部分体の塔を降りる再帰」である。NTT と FFT がその塔と
同じ形をしていないと、木のノードと変換の段が対応しなくなる。

だから遅くても再帰で書く。これは性能を捨てているのではなく、
**バグを 1 箇所に集める**ための設計だ。NTT と FFT が同じ `split`/`merge` の
上に乗っていれば、片方のズレはもう片方との不一致として現れる。
2 つの無関係なバグではなく、1 つの共有された考え違いとして見える。

なお **C 参照実装の `Zf(to_ntt_monty)` はビット反転 + Montgomery** であり、
Python 版とは係数の順序が違う。だからモジュール 4 の突き合わせ相手は
Python 側にしてある（C と比べるには置換と Montgomery 係数の補正が要る）。
この差自体が「速い実装と読める実装は別物である」ことの実例で、
FALCON がその 2 つを両方持っている理由が 4.8 の表そのものである。
