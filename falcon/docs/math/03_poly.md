# モジュール 3: 環 R = Z[x]/(x^n+1) ― 符号 1 個が 3 箇所に現れる

## 3.1 この章で答える問い

FALCON も Dilithium も、同じ形の環を使う。

```
R = Z[x]/(x^n + 1),   n = 2^k
```

Dilithium は `n = 256`, FALCON は `n = 512` または `1024`。
ここまでは同じだ。では**なぜ FALCON では poly.jl を素朴に書く必要があるのか**。
Dilithium なら NTT 一本で済ませられたのに。

答えは、FALCON が**係数体を 3 つ使う**からである。

- `Z_q` 上（公開鍵 `h = g/f`、検証）→ NTT
- `Z` 上、しかも**巨大な係数**（NTRU 方程式 `fG - gF = q` を解く）→ 多倍長
- `C` 上（LDL 分解、Gaussian サンプリング）→ FFT

Dilithium は 1 つ目しか使わない。だから poly.jl は係数型に対して
generic でなければならず、そして generic であるがゆえに
**素朴な O(n²) の実装が、3 つすべての正しさの基準**になる。

## 3.2 なぜ x^n + 1 なのか

`n = 2^k` のとき `x^n + 1` は **2n 次円分多項式** `Phi_{2n}(x)` である。
したがって

```
R = Z[x]/(x^n+1) = Z[zeta_{2n}] = Q(zeta_{2n}) の整数環
```

つまり R は「多項式をある式で割った余り」という便宜的なものではなく、
**円分体の整数環**という由緒正しい対象である。
FALCON が使う構造はすべてこの事実から出る。

1. **部分体の塔**
   ```
   Q = Q(zeta_2) ⊂ Q(zeta_4) ⊂ Q(zeta_8) ⊂ ... ⊂ Q(zeta_{2n})
   ```
   各段の拡大次数は 2。この塔に沿った再帰が、
   FFT・ffLDL・ffSampling・NTRU 求解のすべての骨格になる。

2. **共役と随伴**
   `zeta -> zeta^{-1}` は R の自己同型。これが `adj` である。

3. **ノルム写像**
   `N: Q(zeta_{2n}) -> Q(zeta_n)` が塔を 1 段降りる写像。
   モジュール 6 の主役。

Dilithium は `n = 256` で同じ環を使うが、**塔を降りない**。
NTT で `Z_q` を 256 個の 1 次式に分解して終わりである。
FALCON は塔そのものを再帰の骨格に使うので、
「x^n+1 が円分多項式である」ことが本質的に効いてくる。

## 3.3 負巡回性 ― 符号 1 個の話

`x^n = -1` なので、積は

```
(f * g)_k = sum_{i+j=k} f_i g_j  -  sum_{i+j=k+n} f_i g_j
```

「はみ出した分は符号を反転して先頭に戻す」。これが**負巡回畳み込み**。
`x^n - 1`（巡回）なら符号は反転しない。

この符号は、独立に見える 3 箇所に現れる。

| 場所 | 現れ方 |
|:---|:---|
| `poly.jl` | 上の式の `-` |
| `ntt.jl` | **2n 乗根**が必要（n 乗根では足りない） |
| `fft.jl` | `splitfft`/`mergefft` の回転因子 |

### なぜ NTT に 2n 乗根が要るのか

`x^n - 1 = prod_{j=0}^{n-1} (x - w^j)`（`w` は原始 n 乗根）だから、
巡回環なら n 乗根で十分。しかし

```
x^n + 1 = prod_{j=0}^{n-1} (x - zeta^{2j+1}),   zeta = 原始 2n 乗根
```

`x^n+1` の根は 2n 乗根のうち**奇数乗のもの**であって、n 乗根ではない。
だから `q ≡ 1 mod 2n` が要る。`q = 12289 = 3*2^12+1` はこの条件を満たす。

**これは同じ符号の言い換えに過ぎない。** poly.jl の `-` を直したら
ntt.jl と fft.jl も必ず確認する、というのはそういう意味である。

## 3.4 随伴 adj ― Gram 行列がなぜ意味を持つか

```
adj(f)(x) = f(x^{-1}),  すなわち  adj(f)_0 = f_0,  adj(f)_i = -f_{n-i}
```

`i >= 1` に符号が付くのは、`x^{-i} = x^{n-i} * x^{-n} = -x^{n-i}` だから。
ここでも `x^n = -1` が効いている。**4 箇所目**と数えてもよい。

### 意味

R を `C^n` に埋め込む。`x^n+1` の n 個の根（2n 乗根の奇数乗）で評価する写像

```
f  |->  (f(zeta^1), f(zeta^3), ..., f(zeta^{2n-1}))
```

これがまさに fft.jl のやることだ。この埋め込みの下で:

- `f` を掛ける操作 → 各成分に評価値を掛ける（対角行列）
- `adj(f)` → **各成分の複素共役**（根が共役対を成し `conj(zeta) = zeta^{-1}` だから）

したがって

```
<f * a, b> = <a, adj(f) * b>
```

`adj` は「f を掛ける」線形作用素の**エルミート随伴**である。
だから `f * adj(f)` は自己随伴かつ半正定値、いわば `|f|^2` の多項式版。
実際、`f * adj(f)` の定数項は `||f||^2` に等しい
（テストで検証している）。

FALCON の Gram 行列

```
G = B * adj(B)^T,   B = [[g, -f], [G, -F]]
```

はこの積でできている。**エルミート・半正定値だから LDL* 分解ができる**、
というのがモジュール 8 の出発点であり、
その根拠が `adj` の符号 1 個に載っている。

> 符号を落とすと Gram 行列がエルミートでなくなり、LDL の対角成分が負になり、
> `sqrt` が `NaN` を返す。そして NaN は伝播するので、
> **エラーが出る場所と原因の場所が遠く離れる**。debug_log にこの罠を
> 先回りして書いておく価値がある種類のバグ。

## 3.5 多倍長がどこで必要になるか

素朴な積のアキュムレータは、係数上界を `B` として

```
|acc| <= n * B^2
```

に達しうる。

| 場面 | B | n B^2 | Int64 (9.2e18) |
|:---|---:|---:|:---|
| `Z_q` 上 (n=1024) | 12288 | 1.5e11 | 余裕 |
| f, g（鍵生成の入力） | ~20 | 2e5 | 余裕 |
| **F, G（NTRU 求解の中間）** | ~10^9 以上 | **5e20** | **溢れる** |

3 行目が問題である。NTRU 方程式 `fG - gF = q` を塔に沿って降りて解くとき、
下の段で得た解を上の段に持ち上げる過程で係数が爆発する
（Babai reduction で縮める前の中間値）。ここは `BigInt` が要る。

本実装の `polymul` は、アキュムレータを `widen(T)` に取り
（`Int64` なら `Int128`）、最後に `T` へ**検査つきで**縮める。
入らなければ `OverflowError` を投げる。**黙って wrap しない**のが要点で、
黙って wrap すると「鍵生成はたまに成功する」という最悪の症状になる。

`test_poly.jl` には、係数 ~10^9・n=64 で
**わざと Int64 に収まらない**ベクタを入れてある。
`BigInt` では正解を返し、`Int64` では例外が飛ぶことを両方テストしている。

## 3.6 split / merge ― 塔を降りる操作の係数版

```
f(x) = f0(x^2) + x * f1(x^2)
```

`f in Z[x]/(x^n+1)` を、`f0, f1 in Z[x]/(x^{n/2}+1)` の 2 つに分ける。
偶数次と奇数次に分けるだけの操作だが、代数的には

> `Q(zeta_{2n})` の元を、部分体 `Q(zeta_n)` 上の基底 `{1, zeta_{2n}}` で展開する

ということをしている。塔を 1 段降りる。
FALCON の再帰アルゴリズムはすべてこの分解の上に乗る:

| アルゴリズム | 再帰の実体 |
|:---|:---|
| FFT | split して 2 つの半分サイズの FFT |
| ffLDL | split して 2 つの部分木 |
| ffSampling | 木を降りながら各ノードでサンプリング |
| NTRU 求解 | field norm で降り、解いて、持ち上げる |

`fft.jl` の `splitfft`/`mergefft` は**同じ操作を FFT 領域で見たもの**であり、
係数領域の split と可換でなければならない。
FFTW を使わず自前で書く理由はここにある:
FFTW が与えるのは「FFT」であって、**仕様の木構造と対応した FFT** ではない。

## 3.7 Dilithium との対比（まとめ）

| | Dilithium | FALCON |
|:---|:---|:---|
| 環 | `Z_q[x]/(x^256+1)` | `Z[x]/(x^n+1)`, n=512/1024 |
| 係数の住む場所 | `Z_q` のみ | `Z_q`, `Z`(多倍長), `C` |
| 素朴な畳み込み | 不要（NTT で完結） | **必要**（3 つの高速版すべての基準） |
| 随伴 `adj` | 使わない | Gram 行列の土台 |
| 塔 / split | 使わない | すべての再帰の骨格 |
| 多倍長 | 不要 | NTRU 求解で必須 |

Dilithium の `poly.c` は薄い。FALCON の `poly.jl` が厚いのは、
**同じ環に対して 3 通りの見方をしなければならない**からで、
その 3 通りをつなぐのが「x^n = -1」という符号 1 個である。
