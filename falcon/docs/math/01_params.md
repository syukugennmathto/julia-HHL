# モジュール 1: パラメータ ― 4 つの σ はどこから来るのか

## 1.1 この章で答える問い

FALCON-512 のパラメータ表を眺めると、こういう数が並んでいる。

| 記号 | 値 (n=512) |
|:---|---:|
| `n` | 512 |
| `q` | 12289 |
| `sigma` | 165.7366171829776 |
| `sigma_min` | 1.2778336969128337 |
| `sigma_max` | 1.8205 |
| `beta^2` | 34034726 |

Dilithium のパラメータ表（`q = 8380417`, `eta = 2`, `gamma1 = 2^17`, ...）を
見慣れた目には、まず**桁がおかしい**。q が 3 桁も小さいのに、σ が 165 もある。
しかも σ が 4 種類ある。この章は「なぜこの値なのか」を、
値そのものではなく**値を決めている不等式**の側から説明する。

## 1.2 q = 12289 ― なぜこんなに小さいのか

`q = 12289 = 12 * 2^10 + 1 = 3 * 2^12 + 1`。

NTT のために必要なのは `2n | q - 1` である。負巡回環 `Z_q[x]/(x^n+1)` を
1 次式に完全分解するには **2n 乗根**が要る（n 乗根では足りない。理由は
モジュール 3・4 で扱う）。`q - 1 = 3 * 2^12` なので `2^12 = 4096` までの
2 冪が取れ、`2n = 2048` (n=1024) は余裕で割り切る。

問題は**なぜ 12289 で足りるのか**。Dilithium は `q = 8380417 ≈ 2^23` を使う。
違いは安全性の出所にある。

- **Dilithium (Module-LWE)**: 秘密は小さいベクトル `s`、公開は `t = As + e`。
  安全性は「`q` に比べて誤差が小さい」ことから来る。つまり
  **`q` と誤差の比**が効くので、`q` を大きく取る必要がある。
- **FALCON (NTRU + GPV)**: 秘密は短い基底 `[[g, -f], [G, -F]]`、
  公開は `h = g/f mod q`。安全性は「この格子に**短いベクトルが存在すること**を
  知らないと署名を作れない」ことから来る。格子の行列式は `q^n` で固定されており、
  短い基底のノルムは `sqrt(q)` のオーダーになる。ここで `q` を大きくすると
  基底が長くなり、**署名も長くなって**しまう。

つまり FALCON にとって `q` は「大きいほど安全」ではなく、
**NTT が回る最小の素数を取るのが最適**なのである。
FALCON-512 の署名が 666 バイト（Dilithium2 の 2420 バイトの 1/3 以下）で済むのは、
根本的にはこの設計判断の帰結だ。

## 1.3 1.17 ― Gram-Schmidt ノルムの上限

鍵生成は `f`, `g` を引いたあと、次を満たさなければ**引き直す**。

```
||B~||^2 <= 1.17^2 * q          (ntrugen.py:232)
```

`B~` は NTRU 基底の Gram-Schmidt 直交化。なぜ `sqrt(q)` の定数倍かというと、
基底行列の行列式が `q^n` で、2n 次元格子だから、
「完全に直交した理想的な基底」の各ベクトル長は `q^(n/2n) = sqrt(q)` になる。
`1.17` は「理想からどれだけ悪くてよいか」の許容係数である。

この定数は**署名の長さと安全性の両方を同時に決めている**。
大きくすれば鍵生成は速くなるが（引き直しが減る）、署名が長くなる。

## 1.4 σ ― 3 つを区別する

### `sigma_min`, `sigma_max`: Z 上の各座標の Gaussian

`ffSampling` は再帰の各ノードで「整数を 1 つ、中心 μ・幅 s の離散 Gaussian から
引く」ことをする。その `s` はノードごとに違う（LDL 分解の対角成分で決まる）が、
必ず `[sigma_min, sigma_max]` に入っていなければならない。

- **下限 `sigma_min`** は**平滑化パラメータ** `eta_eps(Z)` である。
  離散 Gaussian が「格子の周期性を十分ぼかしている」ための最小幅で、

  ```
  eta_eps(Z) = (1/pi) * sqrt( (1/2) * ln(2 * (1 + 1/eps)) )
  ```

  `eps` は許容する統計距離。参照実装の値を逆算すると
  `1/eps = 2^32 * n^(3/2)`、すなわち `eps = 1/sqrt(2^64 * n^3)` になる
  （`log2(1/eps)` がぴったり 45.5 と 47.0 になる。debug_log #003 参照）。
  これより狭いと、サンプルが格子点の位置情報を漏らす。

- **上限 `sigma_max = 1.8205`** は理論的な上限ではなく、
  **実装の都合**である。基底サンプラは「幅 1.8205 の半 Gaussian」の
  累積分布表（CDT）を焼き込んでおり、任意の `s <= 1.8205` はそこからの
  棄却サンプリングで作る。だから 1.8205 は「表に焼いた値」であって、
  導出される値ではない。

### `sigma`: 格子上の Gaussian

署名 `(s1, s2)` は格子上の離散 Gaussian から引かれる。その幅が

```
sigma = 1.17 * sqrt(q) * sigma_min = ||B~||の上限 * eta_eps(Z)
```

これは GPV/Klein サンプラの標準的な安全条件
「幅 >= ||B~|| * eta_eps(Z) なら出力が基底に依存しない」の、
FALCON の基底への当てはめそのものである。
**`sigma` が `sigma_min` を含んでいる**のが要点で、だから σ が 4 つあっても
本質的に独立なのは `1.17`, `q`, `eps`, `1.8205` の 4 つだけ。

### `sigma_fg`: 鍵生成の f, g の Gaussian

```
sigma_fg = 1.17 * sqrt(q / (2n))
```

`f`, `g` の各係数をこの幅で引くと、`(f,g)` の全体のノルムが
ちょうど `1.17 * sqrt(q)` 付近になる（2n 個の座標があるので `/(2n)`）。
つまり **1.3 の受理条件を高確率で満たすように逆算された幅**である。

実装上の注意: 参照実装は `n` によらず**常に 4096 個**のサンプルを
幅 `1.43300980528773 = 1.17*sqrt(q/8192)` で引き、`4096/n` 個ずつ足し合わせる。
独立な Gaussian を `k` 個足すと幅が `sqrt(k)` 倍になるので分布は一致するが、
**PRNG の消費バイト列が変わる**ので、KAT を通すには手順まで再現しなければならない。

## 1.5 beta^2 ― 検証の閾値

検証は `||(s1, s2)||^2 <= beta^2` を見る。参照実装の値は
`floor(beta^2)` そのもので、**閾値は inclusive**（`<=`）である
（`common.c:239` に "These bounds are _inclusive_" と明記）。

正直な署名の期待二乗ノルムは `2n * sigma^2` である
（2n 座標、各座標の分散 `sigma^2`）。n=512 なら約 `2.81e7`。
これに対し `beta^2 = 3.40e7` なので比は約 1.21。
つまり**閾値は期待値のわずか 2 割増し**で、余裕はほとんど無い。

この「余裕の無さ」は原稿の伏線として使える:
FALCON は「短い署名」を売りにしているので閾値を切り詰めており、
その結果 `sigma` の実現値がわずかにずれるだけで検証が落ちる。
浮動小数点誤差が効いてくる余地がここにある。

## 1.6 Dilithium との対比（まとめ）

| | Dilithium (ML-DSA) | FALCON (FN-DSA) |
|:---|:---|:---|
| 困難性 | Module-LWE / Module-SIS | NTRU + SIS |
| 署名の作り方 | Fiat-Shamir with aborts（**棄却**） | Hash-and-sign（**Gaussian サンプリング**） |
| `q` | 8380417 ≈ 2^23（大きいほど良い） | 12289 ≈ 2^13.6（NTT が回る最小） |
| 秘密の分布 | 一様（`|c| <= eta`） | 離散 Gaussian |
| 浮動小数点 | **使わない** | Float64 が仕様の一部 |
| 署名長 (128bit) | 2420 B | 666 B |
| 実装の難所 | 棄却率、NTT の Montgomery 化 | **定数時間な Gaussian サンプリング** |

最後の行が、この本全体の問いである。
「NIST PQC 4 方式のうち、なぜ FN-DSA だけ標準化が遅れたのか」の答えは、
パラメータ表のこの `sigma_max = 1.8205` という中途半端な数と、
それが浮動小数点の CDT 表であるという事実に、すでに埋め込まれている。
回収はモジュール 7・8 で行う。
